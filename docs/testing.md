# Testing

`go test -race ./...`

- `internal/security/trust_test.go` — trust store: add/lookup/persist/0600; **revocation by another process takes effect at once** (and fails when the reload is removed); corrupt or deleted file fails closed; hand-edited entries rejected; sliding expiry (use extends, idleness lapses, expired entries stay listed, re-trust revives); expiry `0` means never; names sanitised; sender-side hint is only a hint.
- `internal/transfer/trust_test.go` — lifecycle (untrusted without PIN refused and nothing written → PIN + user yes grants trust → next send needs no PIN → revoke → PIN required again); declining the offer stores nothing; **trust is bound to the key** (same name, different key gets nothing); trust only after a verified transfer; never created from a PIN-less session; expiry falls back to PIN; trusted use leaves lockout counters untouched; receiver consent still required; forged hello ID rejected for trusted senders; no trust store means no trust. Mutation-checked: each of these fails if its guard is removed.
- `internal/transfer/transfer_test.go` — sender↔receiver over real loopback TCP: small, empty, 24 MiB, spaces, Unicode, duplicates (rename/replace), decline, path traversal (`../`, `..\`, absolute, drive), corrupted data, truncated stream, invalid size/hash/mode, version mismatch, context cancellation, progress.
- `internal/discovery` — ARP parsing for macOS, Windows and Linux formats (incomplete, broadcast, multicast and link-local entries dropped; single-digit MAC octets padded), private/random MAC detection, subnet probe targets (a /24 is 253 targets without network, broadcast or self; a /16 is clipped to a /24; a /26 stays inside its range), reverse mDNS name/answer parsing, NetBIOS node-status parsing (group names are not machine names; truncated and hostile packets do not panic), service descriptions, sort order (ready first, then named, then numeric IP). Mutation-checked.
- `internal/security` — PIN format/generation/Argon2id verifier (and production KDF parameters), PIN store (no plaintext, 0600, change invalidates old PIN, corrupt/weak files rejected), limiter (lockout, exponential backoff, cap, persistence across restart, corrupt state fails closed, success resets), PIN authorization over real TLS (correct/wrong/near-miss indistinguishable, lockout refuses the right PIN, abandoned attempts count, malformed PINs, **relay man-in-the-middle fails**, **replayed auth messages fail**, stalled-sender timeout, hostile Argon2 parameters, **PIN absent from wire frames, disk and logs**), TLS identity pinning, plaintext peer rejected, TLS 1.3 enforced, channel-binding uniqueness, policy table.
- `internal/transfer/transfer_test.go` — sender↔receiver over real TLS + PIN: small/empty/24 MiB/Unicode/spaces files; wrong PIN writes nothing; **unauthenticated file request refused**; text without PIN (default) and with `text_requires_pin`; oversized/corrupted text; duplicates (rename/replace); decline; path traversal (even when authorized); corrupted and truncated data; invalid size/hash/mode and unimplemented `clipboard` mode; plaintext client rejected; receiver/sender refuse to run without TLS; v1 peer rejected; spoofed hello ID rejected; cancellation; progress; logs contain no PIN or file contents.
- `internal/transfer/manifest_test.go`, `folder_test.go` — manifest validation (traversal, absolute/drive/backslash, NUL, duplicates, case and unsafe-character collisions, missing/late parents, file-as-directory, depth/length/overflow, unknown fields, a 2000-input property check that validated paths never contain unsafe components); end-to-end folders over real TLS + PIN: nested tree with Unicode/spaces/empty files/empty folders/exec bit/5 MB file, empty folder, existing folder never merged or replaced, unauthorized and wrong-PIN folders write nothing, hostile manifests rejected before anything is written (and nothing escapes the destination), summary/hash mismatches, absurd manifest size, corrupted file aborts the whole folder and leaves nothing, truncated stream, stalled sender times out, symlink swapped in after scan not followed, file modified after scan detected, decline.
- `internal/project` — gitignore semantics (40 cases: anchoring, `**`, negation, directory-only, classes, escapes, CRLF, nested bases, malformed input) **and parity with real `git ls-files --others --exclude-standard`** on a tree with nested ignore files (verified to fail when the matcher is deliberately broken); project detection (README alone is not a project; subfolders do not inherit); secret names (positives and look-alike negatives such as `.env.example`, `id_rsa.pub`, `keyboard.txt`); content detection (7 formats, example key not flagged, binary/oversized skipped, findings never leak the secret); scan rules (what is excluded and why, directory sizes measured, `--include-secrets`, plain folders only get secret protection, `--all`, `target/` only for Rust/Java, `venv` only when it has `pyvenv.cfg`, nested `.gitignore` with negation, `.git/info/exclude`).
- `internal/transfer` — also an end-to-end test that excluded secrets and generated folders are absent from the manifest and from the receiver's disk.
- `internal/git` — against real `git`: branch/detached/unborn detection, change classification (modified, staged vs unstaged, untracked, deleted, renames with spaces and Unicode, ignored files, merge conflicts refused); **the patch reproduces the working tree**: a patch for modify/binary/mode-change/delete/rename/staged-add/untracked/empty files is `git apply`-ed to a clean clone of the base commit and the trees compared; staged-only patches; path selection leaks nothing excluded and never globs (`*.txt`); 600 long paths are chunked; **the repository is byte-for-byte unchanged** (whole `.git` hashed before/after, with a premise check that plain `git diff` really would rewrite the index, and verified to fail when isolation is disabled); the private index copy keeps the original index's mtime (git's "racily clean" check depends on it; found via an intermittent failure, pinned by a test that fails when the mtime is not preserved); bundles clone with history and the right checked-out branch (verified to fail when `HEAD` is left out), exclude uncommitted work, honour `--all`, refuse detached/empty; history scan finds files deleted later; missing `git` binary. Also verified by hand with two real processes and pseudo-terminals: first-run PIN generation, masked PIN prompt, wrong PIN then right PIN in one session (hashes equal), three wrong PINs → lockout, correct PIN refused while locked, `--text` from a pipe without a PIN while locked, and no PIN in any file under either config dir; trusted devices with a receiver in a pseudo-terminal (offer and accept, second send with no PIN anywhere, `✓ Trusted device` on the receiver, listings, PIN absent from `trusted.json`/`pin.json`, revocation from a third process while the receiver keeps running, sender fallback and hint cleanup, PIN path working again); `drop <folder>` and `drop .` with 1,506 files / 194 MB including a symlink, an empty folder and an executable, compared with `diff -r`; `drop diff --patch` on a repository with a modified, deleted, renamed, staged-added, untracked and binary-changed file plus a withheld `.env` and AWS key, with the received patch `git apply`-ed to a pristine copy of the base commit (identical tree), `--files`, `--staged`, `drop git` (cloned from the received bundle), the history guard, and an unchanged `.git` fingerprint; and `drop .` on a real `git init` project with 20,061 files (including a 20,000-file `node_modules`, a virtualenv, secrets, an embedded AWS key and a symlink): classification took 0.8 s, and the receiver got exactly the 6 source files.

Benchmarks: `go test -run xxx -bench . ./internal/transfer`. Manual (not automated): the interactive device picker (needs a TTY), real mDNS across two physical machines, Windows runtime behaviour (cross-compiled only), firewall prompts.

## Smoke test
`scripts/smoke.sh` (`make smoke`) drives the real binary with two instances and separate identities: receiver start and PIN generation, discovery, a 3 MB file (byte-compared), plain text, a project folder (source arrives; `.env`, `node_modules`, `.git` and secret content do not), a Git patch (applied with `git apply --check`), a wrong PIN (exit 4), lockout, and that nothing was written by failed attempts. It was verified to fail when secret exclusion is deliberately broken, and to leave no processes behind.
